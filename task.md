## Approach

Build in dependency order (credentials → money rail → inbox → brain → approval → wiring → loop → safety → ship), proving each layer against the real sandbox before layering the next. Postgres stays the source of truth per explain.md; the model only ever fills a fixed JSON schema and never sees PayPal credentials or tools.

## Key Decisions

1. **PayPal REST for money; toolkit for read-only agent data.** Invoice create/send and Payouts execute through plain REST (`POST /v2/invoicing/invoices`, `.../send`, `POST /v1/payments/payouts`). `@paypal/agent-toolkit` supplies **read-only** invoice/transaction/dispute tools to the AI agent; its `send_invoice`, `pay_order`, `create_refund`, `record_payment/refund`, order and subscription tools are disabled by configuration, so the model never gets money-moving access. The toolkit has no Payouts or balance tools, so those stay direct REST.
2. **Idempotency in two layers.** Our `idempotencyKey` (unique, DB-enforced) derives PayPal's `sender_batch_id` for payouts via `sha256("batch:"+key)` hex-sliced to 30 chars (deterministic across retries, safe for PayPal's short sender fields), and we send the raw key as PayPal's `PayPal-Request-Id` header on payout calls. State transitions stay single-sourced `UPDATE WHERE status=` per explain.md §5.
3. **Webhooks verified by calling PayPal.** Handler posts every event to `POST /v1/notifications/verify-webhook-signature` before trusting it, then dedupes on `ProcessedWebhook(eventId)`.
4. **Gmail: full sync once, then `historyId` polling.** First run does `messages.list` + `messages.get` and stores the newest `historyId`; the ~60s poller uses `history.list(startHistoryId)` and falls back to full sync when history expires.
5. **Telegram: `nestjs-telegraf` + inline callback buttons.** Cards use inline keyboard buttons carrying `callback_data` with only the action ID; long-poll locally, webhook (`setWebhook`) on the deployed host. Caution: the package's repo has changed owners (README badges point at `0x467`, GitHub now resolves `bukhalo/nestjs-telegraf` to `nksmnf/nestjs-telegraf`) — re-verify the Nest peer range at install time and keep Nest 10 unless peers prove otherwise.
6. **One active provider: Vultr Serverless Inference (OpenAI-compatible).** `.env` sets `META_MODEL_URL=https://api.vultrinference.com/v1` and `META_MODEL_NAME=deepseek-v4.1-flash-1017`; the probe verifies `POST {META_MODEL_URL}/chat/completions` with a Bearer key. `LlmProvider` remains the seam so the endpoint/model can change without touching product code. The `ANTHROPIC_*` vars and `@anthropic-ai/sdk` are **not used** — Claude is out of the stack.
